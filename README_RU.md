**c2plan9** — это высокопроизводительный конвейер компиляции и дизассемблирования машинного кода, преобразующий исходные файлы C, C++ и LLVM IR в ассемблер Plan 9 (`.s`), совместимый с компилятором Go, с автоматической генерацией сопутствующих Go-стабов (`.go`).

## Зачем нужен c2plan9?

Высокопроизводительное системное программирование на Go часто требует аппаратной SIMD-векторизации (AVX2, AVX-512, NEON, GFNI). Однако:
1. **Задержки вызовов CGO**: Вызов внешних C-библиотек через CGO создает накладные расходы в 40–150 нс на каждый вызов, нивелируя преимущества векторных микроядер.
2. **Сложность ручного ассемблера Plan 9**: Написание ассемблерного кода Plan 9 вручную для сложных векторных инструкций подвержено ошибкам и трудно поддается верификации.
3. **Решение `c2plan9`**: Вы пишете чистые, оптимизированные интринсики на C, а `c2plan9` компилирует их через Clang/LLVM в переносимый объектный формат ELF, дизассемблирует в синтаксис Plan 9 и генерирует типизированные Go-заглушки.

## ⚡ Ключевые возможности

- **Поддержка двух ключевых архитектур**:
  - **AMD64**: AVX2, AVX-512, FMA, PCLMULQDQ, AES-NI, BMI1/2.
  - **ARM64**: Векторизация NEON, криптографические расширения (AES, SHA1, SHA2, PMULL).
- **Переносимая генерация ELF-объектов**: Принудительная установка флага `-target x86_64-pc-linux-gnu` или `aarch64-linux-gnu` на любых хост-системах (Windows, Linux, macOS), исключающая платформенные расхождения форматов (релокации PE, манглинг символов Mach-O).
- **Типизированный фрейм возврата**: Полная поддержка скалярных типов (`int`, `int32`, `float32`, `float64`) и 128/256-битных SIMD-векторов (`m128`, `m256`) с генерацией инструкций перемещения регистров (`VMOVDQU`, `FMOVQ`) во фрейм Go.
- **Сохранение выравнивания стека**: Корректное сохранение инструкций динамического выравнивания стека (`ANDQ $-32, SP`) с расчетом паддинга, предотвращающее сбои при векторных обращениях к памяти (`VMOVDQA`).
- **Генерация Go-стабов**: Автоматическое создание сопутствующих `.go` файлов с аннотациями `//go:noescape`.
- **Интеграция с WSL**: Нативная работа под Windows с возможностью вызова Clang внутри WSL через флаг `-wsl`.

## ⚠️ Архитектурные ограничения и правила проектирования

`c2plan9` спроектирован специально для **вычислительных SIMD-микроядер**, а не как замена универсального Си-компилятора. При написании ядер на Си необходимо соблюдать следующие архитектурные инварианты:

1. **Исключительно листовые функции (Leaf Functions)**:
   - Си-ядра должны быть чистыми листовыми функциями. Запрещены вызовы внешних функций (`call foo`), стандартной библиотеки (`printf`, `memcpy`, `malloc`) или системных вызовов.
   - Вся внешняя память должна передаваться напрямую через указатели из Go.
2. **Ограничения на количество аргументов**:
   - **AMD64**: Не более 6 целочисленных аргументов/указателей (передаются через регистры System V: `RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9`).
   - **ARM64**: Не более 8 аргументов (передаются через регистры AAPCS64: `R0`–`R7`).
   - *Примечание*: Срез в Go занимает сразу 3 слота параметров (`ptr`, `len`, `cap`). Если ядру требуется много буферов, передавайте их через указатели на структуры.
3. **Передача векторных данных по указателям**:
   - Векторы SIMD на вход должны передаваться по указателю (`const uint8_t* in`, `const __m256i* data`), а не по значению в сигнатуре. Возврат векторов по значению (`-ret=m256` или `-ret=m128`) поддерживается в полном объёме.
4. **Запрет на таблицы переходов (Jump Tables)**:
   - Ветвления `switch` не должны порождать таблицы переходов в `.rodata`. `c2plan9` принудительно передает флаг `-fno-jump-tables`, разворачивая switch в бинарное дерево сравнений `CMP`/`JE`.
5. **Автономное окружение (Freestanding)**:
   - Компиляция выполняется с флагами `-ffreestanding`, `-fno-stack-protector` и `-fomit-frame-pointer`. Инициализация рантайма Си (CRT) отсутствует.

## 🛠️ Использование

### Флаги командной строки

```text
Usage of c2plan9:
  -c string
        Путь к исходному файлу C / C++ / LLVM IR (обязательный)
  -o string
        Путь к результирующему файлу ассемблера Plan 9 (.s)
  -stub string
        Путь к результирующему файлу Go-стаба (.go)
  -pkg string
        Имя целевого Go-пакета (по умолчанию имя директории вывода)
  -arch string
        Целевая архитектура: amd64 (по умолчанию) или arm64
  -clang string
        Путь к исполняемому файлу Clang (по умолчанию "clang")
  -flags string
        Дополнительные флаги компилятора Clang
  -ret string
        Тип возвращаемого значения: float32, float64, m128, m256, int, int32 или void
  -wsl
        Компиляция через Clang внутри WSL
```

### Пример с `//go:generate`

В вашем Go-пакете:

```go
//go:generate c2plan9 -c ../csrc/fastscan.c -o fastscan_amd64.s -stub fastscan_amd64.go -pkg simd
```

Запуск генерации:
```bash
go generate ./...
```
